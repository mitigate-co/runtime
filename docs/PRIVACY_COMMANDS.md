# Verify privacy and inspect egress

These local commands need no Platform account, network connection or credentials.
They report the installed implementation, not certification or proof of an entire
deployment's behavior. Enrollment, authenticated signing and a sender are separate
MCP-018 work; this build has no configured Platform destination.

## Run the privacy self-test

```sh
mitigate privacy self-test
mitigate privacy self-test --json
```

The probe injects 147 hostile candidates across eleven fixture families into the
production queue admission path. It includes synthetic API keys, unsigned JWT-like
tokens, email, SSN/card-shaped values, source code, high-entropy/long text, nested
unknown objects, prohibited fields and ambiguous/oversized JSON. Each string
family is tried in every supported string-reference/enum position and capabilities.

A known-safe event must still be accepted and deduplicated. Every hostile event
must be rejected, only that positive control may remain pending, rejection counts
must match and none of the synthetic content markers may appear in database bytes.
There are no real customer inputs or sender calls. Reports contain category names
and counts only, never synthetic secret values, raw queue payloads or paths.

The probe creates a private exclusive directory under the OS temporary directory
and removes it before reporting success. It never opens a real user queue or
native credential store. To choose an existing writable parent on another volume:

```sh
mitigate privacy self-test --work-dir . --json
```

Exit 0 means all checks passed; exit 1 means a privacy assertion failed; exit 2
means the probe could not complete, including setup/storage/cleanup errors. Keep
optional synchronization disabled when checks fail. Correct storage/toolchain
issues and rerun; an unavailable test is not a privacy pass.

## Inspect this build's contract

```sh
mitigate egress inspect
mitigate egress inspect --json
```

This shows the exact supported event type, schema version, field paths and byte
limit. With no queue selected, observed types/versions are empty and the queue is
null. Supported fields are not evidence that any event has been sent.

To inspect an existing queue, supply its independently configured scope:

```text
mitigate egress inspect --db <existing-queue> --runtime-ref <runtime-reference> --enrollment-ref <enrollment-reference> --json
```

Angle-bracket values are placeholders, not a runnable enrollment command. Queue
references are generated by the local integration and have the exact shape
`ref_` plus 32 lowercase hexadecimal characters. Do not substitute fingerprints,
credentials or customer labels. The actual CLI test creates a synthetic scoped
queue and exercises this command. There is no raw queue-import command. Optional
enrollment and [explicit sync controls](SYNC_CONTROLS.md) are separate actions.

The report shows retained event/byte/lease/receipt counts, fixed admission/delivery
counters, bounded recent rejection reasons, observed type/version and retention
settings. Version-one outboxes admit only `mcp_tool_decision` v1; observed types
and versions derive from validated queue state, never arbitrary database strings.
Lifetime accepted counters can remain after purge. The report is local diagnostic
metadata and must not be sent directly to Platform.

Inspection opens SQLite read-only, verifies the full bounded store and checks the
runtime/enrollment pair. It does not create, prune, recover a write journal, change
permissions or modify database bytes. Expired rows/leases may remain until the
queue worker applies maintenance. A corrupt, wrong-scope, unsafe or unavailable
store exits 2 with a fixed error and no partial report or path/content echo.

Inspection report version 2 returns `destination: null` and
`delivery_status: "not_checked"`: this read-only command does not open a sync
profile or native enrollment. It must not infer that delivery is unconfigured.
Use `sync status --profile PROFILE` to inspect consent for the selected binding.
Version 1's unconditional unconfigured claim is replaced; the event contract,
outbox schema and privacy self-test report remain version 1. Queue acceptance and
an independently reported delivery acknowledgment are distinct facts.

## Development verification

```sh
cargo test -p mitigate-egress --locked
cargo test -p mitigate-cli --test privacy --locked
cargo run -p mitigate-egress --example self_test --locked
```

The last command executes the same synthetic probe without building unrelated
CLI dependencies. It does not replace actual shipped-CLI testing. CI runs both
commands and subprocess tests on Windows, macOS and Linux. The broader hostile
corpus, signed releases and enrolled end-to-end delivery remain production gates.
